# Kit — архитектурный дизайн (v1)

> **Статус:** дизайн-черновик для v1. Фиксирует решения, принятые в обсуждении
> 2026-06 (после интеграции ViennaRNA `RNAfold` в WASI-платформу).
> **Обновление 2026-06 (манифест-штурм):** зафиксирован стандарт манифеста
> (вызываемая поверхность ≠ `kit.json`), режимы `strict`/`loose`, единый тул
> `compute`, pre-flight-валидация, слои тестов и модель recipe-as-data — см.
> §5.3, §6, §12 и прецеденты в §16.
> **Язык реализации сущности:** `Kit`. **Папка:** `kits/`. **Привязка:** `domain → kits`.
> Сущность встаёт в один ряд с `domain / workspace / skill / kit` — односложные
> образные существительные.
> **Полная разбивка текущих ассетов на 36 китов:** [asset-inventory.md](asset-inventory.md).

## 0. TL;DR (одна страница)

**Kit** — первоклассная сущность Foundation: переносимая, изолированно
исполняемая научная способность. Один upstream-проект на одной версии,
содержащий **≥1 артефакт** (wasi-бинари и/или Pyodide-`.whl`) + метаданные +
инструкцию для агента + I/O-контракт с golden-примером.

- **Два формат-трека исполнения:** `wasi` (любой компилируемый язык → wasm32-wasi,
  через `node:wasi`) и `pyodide/whl` (Python-стек в WASM-песочнице). Вместе
  закрывают **~75–85% типичных запросов агента**.
- **Единый тул:** агент вызывает Kit через ОДИН инструмент; разница wasi/whl
  спрятана под капотом. **Инвариант:** два санбокса, **общей ФС нет** — тул не
  должен создавать иллюзию общего стейта.
- **Привязка только к домену.** Глобальных Kit нет. Не привязан — агент не
  видит и не может использовать. Размер промта контролируется тем, что
  привязано.
- **Инструкция инжектится в агента всегда** (не ленивая загрузка) — потому что
  привязка per-domain уже ограничивает контекст. Страховка: мягкий бюджет
  ~1–2k токенов на Kit.
- **Дистрибуция:** базовый набор едет в npm как **шаблоны**
  (`packages/found-bundle/bin/templates/kit/`) и при первом запуске
  **сидируется в папку пользователя** — как базовые домены. Хвост — через
  **Library**; скачанные Kit тоже **ложатся в пользовательскую папку** (как
  скачанные домены). Резолв хвоста через **наш хэш-пиннутый реестр**; git —
  только провенанс-метаданные. `sha256` обязателен.
- **Зависимости:** kit→kit и domain→kit. v1: **точные пины + lock-файл +
  fail-loud**, без солвера.
- **Публикация домена:** домен публикуется со **ссылками** на Kit
  (`id@версия+hash`), а не с бинарями. Недостающее юзер ставит сам через Library.
- **Скиллы остаются** — для сквозной методологии; Kit несёт свою usage-доку.
- **Все киты равны:** у каждого `{1+ артефактов, instruction.md, манифест}`.
  Второго сорта нет.
- **Оси кита:** `tags[]` (таксономия, контролируемый словарь) + `tier`
  (default/library). **Нет** `role` и **нет** `category`.
- **capability/dependency — свойство РЕБРА домен↔кит, не кита:** привязан явно →
  инструкция инжектится; приехал транзитивно → грузится в рантайм, не инжектится.
  Один кит в одном домене capability, в другом — транзитивная зависимость.
- **Бэндлинг:** Kit вбэндливает свои **эксклюзивные** зависимости
  (мультиартефактный кит); **общие** зависимости (2+ потребителя) — отдельные киты.

| Что | Решение v1 |
|---|---|
| Формат-треки | `wasi` + `pyodide/whl` (два, третий не добавляем) |
| Вызов | единый тул `compute`, рантайм спрятан, общей ФС нет |
| Манифест | вызываемая поверхность кита (**≠ `kit.json`**); `mode: strict\|loose` |
| strict/loose | strict = именованные операции (argv скрыт); loose = код + import-allow-list |
| Pre-flight | валидация на границе → отказ кривого вызова **до** санбокса |
| Гранулярность | **1 связная инструкция = 1 Kit**; эксклюзивные deps вбэндлены |
| Оси кита | `tags[]` + `tier`; **нет** `role`/`category` |
| capability/dependency | свойство **ребра** домен↔кит, не атрибут кита |
| Видимость | только привязанные к домену Kit |
| Инструкция | инжектятся **явно привязанные**; always-on, бюджет ~1–2k/Kit |
| Зависимости | exact-pin + lock + fail-loud, без солвера |
| Резолв | хэш-пиннутый реестр; git = провенанс |
| Базовый набор | 4 кита (numpy/scipy/sympy + seqtk-wasi) в npm; хвост через Library |
| Лицензии | показываются на установке (слой реестра), не на домене |
| Детерминизм | golden-пример как фикстура; флаг `verified` |

## 1. Контекст и проблема

Foundation уже исполняет научный код в двух WASM-песочницах:

- **WASI-трек** — standalone-бинари, скомпилированные в `wasm32-wasi`, под
  `node:wasi`. Сегодня: `packages/found-bundle/bin/wasm/` → `seqtk.wasm`,
  `RNAfold.wasm` (+ `LICENSE-ViennaRNA`). Вызов через тул `wasmCli`.
- **Pyodide/whl-трек** — Python-стек в WASM. Сегодня:
  `packages/found-bundle/bin/pyodide/` → набор `.whl`
  (biopython, astropy, dendropy, deap, chaospy…), часть pure-Python
  (`py3-none-any`), часть портирована под emscripten
  (`pyemscripten_2025_0_wasm32`). Вызов через тул `mathCompute`. Отдельно
  `bin/rdkit/` → `RDKit_minimal` (MinimalLib-wasm) под `chemAnalyze`/`chemCompare`.

**Проблема масштабирования.** ViennaRNA `RNAfold` показал, что собрать тул в
wasi реально, но каждый бинарь весит 2–3 МБ. Научных тулзов — десятки-сотни
(одна bioconda — 3000+). Бандлить всё в npm-пакет = раздуть его до 50–60+ МБ.
Это тупик: так не масштабируемся. Нужна модель «маленькое ядро + хвост по
требованию».

**Вывод ресерча (см. §16):** все платформы с большим каталогом (biowasm/Aioli,
Pyodide, HuggingFace Hub, conda, Homebrew, Wasmer, VS Code) делают одно — **крошечное
ядро + ленивая загрузка хвоста + локальный кэш по хэшу**. Наш `sha256` уже лежит
в манифесте, так что переход — небольшой шаг, а не переписывание.

## 2. Цели и не-цели v1

**Цели:**
- Ввести сущность `Kit` как единицу упаковки/дистрибуции/привязки научной
  способности.
- Унифицировать вызов wasi + whl в один агентский тул.
- Базовый набор в npm + хвост через Library с резолвом по хэшу.
- Привязка Kit к домену; инструкции и I/O-контракт едут внутри Kit.
- Проверяемость и тестируемость через golden-пример.

**Не-цели v1 (осознанно отложено):**
- ❌ Солвер зависимостей (conda-класс). Только точные пины + fail-loud.
- ❌ Авто-пайплайн тулзов (система сама строит цепочку выход→вход).
- ❌ Нативная Python-песочница (полный PyPI/HPC) — это **v2**.
- ❌ GPU / deep learning / онлайн-БД — структурные дыры, не v1 (часть — никогда
  в песочнице).
- ❌ Ленивая подгрузка инструкций — выбран always-on (см. §7).
- ❌ Третий формат-трек — нечего добавлять (см. §3).

## 3. Две вселенные исполнения (формат-треки)

| | **WASI-трек** | **Pyodide/whl-трек** |
|---|---|---|
| Артефакт | `.wasm` (standalone) | `.whl` (Python-колесо) |
| Из языков | C, C++, Rust, Go(TinyGo), Zig, Swift, Fortran(капризно) | Python + нативка C/C++/Cython/Rust/Fortran, обёрнутая в Python-модуль |
| Рантайм | `node:wasi` (preview1), без JS-glue | Pyodide (CPython в WASM, wasm32-emscripten) |
| Изоляция | свой санбокс на запуск, конфликтов нет | общий интерпретатор — `.whl` делят его, версии могут конфликтовать |
| ФС/сеть | только preopen `/tmp`, сети нет | эмуляция, сети нет |
| Сегодняшний тул | `wasmCli` | `mathCompute` |

**Почему два, а не один.** Индустриальный стандарт «один Python-санбокс, бинари
внутрь через bash» предполагает тяжёлый Linux-контейнер с общей ФС. У нас его
нет намеренно (in-process, оффлайн, лёгкие). Pyodide физически не может
`fork/exec` нативный бинарь. Поэтому два движка — это адаптация под наше
ограничение, а не разнобой.

**Почему не три.** Кандидаты в «третий» мнимые: WASI preview2/Component Model —
эволюция трека №1 (тот же рантайм, позже); другие языки-в-wasm (webR, SQLite-wasm) —
это **контент** на существующем треке, не новый механизм; нативная песочница —
отдельный трек, осознанно v2. Структурную дыру (GPU/потоки/сеть) новым
wasm-форматом не закрыть.

### 3.1. Покрытие — честная калибровка

| Сегмент задач | Покрытие (wasi + whl) |
|---|---|
| Математика/статистика/data wrangling (numpy, scipy, sympy, pandas, sklearn, networkx) | ~90% (ядро Pyodide) |
| Символика/солверы/оптимизация малого-среднего (sympy, pysat, clingo, scipy.optimize) | высоко |
| Биоинформатика на уровне либ (Biopython, выравнивание) | хорошо |
| Биоинформатика CLI (samtools, bwa, seqtk, ViennaRNA, minimap2) | средне-хорошо, но per-tool труд |
| Хеминформатика (RDKit-дескрипторы) | частично (MinimalLib есть, полный API нет) |
| Тяжёлая симуляция / HPC (MD, FEM, MPI) | почти нет → v2 |
| Deep learning / GPU (PyTorch, AlphaFold) | нет → даже v2 без GPU не закроет |
| Онлайн-данные (BLAST/NCBI, KEGG, PDB-fetch) | нет — это сетевая проблема, не формат |

- **По типичным запросам агента** — два формата дают **~75–85%**.
- **По всему научному софту** — мало (длинный хвост огромен, многое требует
  HPC/GPU/сети). Разные знаменатели, оба верны.
- **Три дыры, которые не закрывает никакой sandbox-формат:** GPU/DL, HPC-с-потоками,
  живые сетевые БД. Первые две частично — v2; третью — никогда (нет сети by design).

### 3.2. whl — основной канал, но «дёшев» только в пределах Pyodide

Важная поправка для оценки стоимости (а не usage):

- **whl как поверхность агента** — да, основной канал (большинство задач —
  Python).
- **whl как наш build-канал** — дёшев только для **pure-Python** (уже
  `py3-none-any.whl`) и **уже-портированных ~250** пакетов Pyodide. Добавить
  **нативную** Python-либу в Pyodide ≈ по сложности **то же, что собрать C-тул в
  wasi** (это и есть кросс-компиляция C/Fortran в wasm + биндинг-слой). «Python
  как обёртка над C-движком» и «нативные расширения тяжело портируются» — про
  одно и то же.

### 3.3. Правило выбора канала для способности

1. Есть **Pyodide-готовый Python-пакет** (чистый или уже портирован)? → **whl,
   почти бесплатно**. Дефолт.
2. Нет в Pyodide, но **чистый Python**? → **whl, легко** (вендорим колесо).
3. **Нативный** Python-пакет, которого нет в Pyodide? → порт под emscripten
   (тяжело) либо мимо.
4. **Не-Python компилируемый тул** ИЛИ C-либа только через CLI? → **wasi**. Это
   ViennaRNA.

> Стратегически: **wasi-трек — главный рычаг** для длинного не-Python хвоста (он
> масштабируется на все языки), whl-трек — специализация под Python-стек.

## 4. Сущность Kit

**Kit = упакованная научная способность со всем, что нужно агенту и системе,
чтобы её проверяемо использовать.**

- **Все киты равны и единообразны:** каждый = `{1+ артефактов, instruction.md
  (проза), kit.json (метаданные), manifest.json (вызываемая поверхность)}`.
  Второго сорта («плумбинг без доки») нет — у любого кита есть инструкция и
  манифест, любой можно привязать явно.
- Несёт **провенанс** (откуда, версия, git), **инструкцию** для агента и
  **I/O-контракт** с golden-примером.
- Привязывается **к домену** (как саб-агент/скилл). Глобальных Kit нет.

### 4.1. Гранулярность — «1 связная инструкция = 1 Kit»

Граница кита там, где кончается **одна осмысленная `instruction.md`**. Нельзя
связно описать API 10 разных либ в одной инструкции → это 10 китов. Обычно
совпадает с **одним upstream-проектом**:

- ViennaRNA = 1 Kit (RNAfold + RNAcofold + RNAsubopt — одна связная инструкция «сьют»).
- seqtk = 1 Kit (один бинарь, много подкоманд, одна инструкция).
- biopython ≠ freesasa → 2 Kit (разные проекты, разные доки).

### 4.2. Бэндлинг — эксклюзивные deps внутрь, общие — отдельным китом

- **Эксклюзивную зависимость** (один потребитель) Kit **вбэндливает** как
  дополнительный артефакт → мультиартефактный кит. Напр. `astropy` = astropy +
  pyerfa + astropy_iers_data; `sympy` = sympy + mpmath + gmpy2.
- **Общую зависимость** (2+ потребителя) выносим в **отдельный кит** — потому что
  Pyodide-интерпретатор один: общий пакет нужен в одной версии без дублей. Напр.
  `pytz` (нужен pandas и astropy), `joblib` (scikit-learn и scikit-optimize).
- Поэтому `kit.json → dependencies[]` перечисляет **только общие** киты;
  эксклюзивные лежат прямо в `artifacts[]`.

Это правило резко сокращает число китов и даёт «джойны» (несколько `.whl` в
одном ките). Полная карта — [asset-inventory.md](asset-inventory.md).

## 5. Анатомия Kit — файлы в папке

> Раскладка иллюстративная (имена/поля уточняются на этапе спеки).

```
kits/<kit-id>/
├── kit.json            # метаданные, провенанс, версия, артефакты, зависимости, runtime
├── instruction.md      # агент-facing ПРОЗА: зачем, когда, чего НЕ делать (always-on + бюджет)
├── manifest.json       # вызываемая поверхность: операции/params + golden (источник истины, §5.3)
├── LICENSE             # лицензия upstream (для surfacing на установке)
└── artifacts/
    ├── RNAfold.wasm    # wasi-бинарь(и)  — ИЛИ
    └── *.whl           # Pyodide-колесо(а)
```

Три файла — три потребителя: `kit.json` (резолвер/реестр/привязка),
`instruction.md` (агент, проза), `manifest.json` (валидатор/тесты/дайджест в
промт). Это наш «contract-file» паттерн и зеркало доменного `dcc` (`contractMd`
проза + `schema` структура). **`manifest.json` заменяет ранее предполагавшийся
`contract.json`:** golden теперь живёт внутри манифеста (`operations[].golden`),
а сам манифест — единственный источник истины (recipe-as-data, §5.3).

**Где живут эти папки (как у доменов):**
- **Шаблоны базового набора** — в бандле: `packages/found-bundle/bin/templates/kit/<kit-id>/`.
- **Рабочая копия пользователя** — `${FOUND_KITS_DIR}/<kit-id>/` (предлагается
  `FOUND_KITS_DIR` = `${DATA_DIR}/kits`, по аналогии с `FOUND_DOMAINS_DIR`). Базовые
  Kit **сидируются** сюда из шаблонов при первом запуске; скачанные через Library —
  тоже сюда. Та же двойственность «bundled template → user copy», что у базовых
  доменов.

### 5.1. `kit.json` (иллюстративно)

```jsonc
{
  "id": "viennarna",
  "version": "2.7.2",
  "runtime": "wasi",                 // "wasi" | "pyodide"
  "tags": ["biology", "rna"],        // таксономия, контролируемый словарь (см. §7)
  "tier": "library",                 // "default" (в шаблоне) | "library" (реестр)
  "verified": true,                  // true = собрали мы; false = user-supplied
  "provenance": {
    "source": "git",
    "repo": "https://github.com/ViennaRNA/ViennaRNA",
    "ref": "v2.7.2",                 // мутабельно → доверяем не ему, а sha256 ассета
    "license": "ViennaRNA",          // кастомная; naview.c исключён (нельзя редистрибутить)
    "buildNote": "wasi-sdk-33, --disable-pthreads, naview excluded"
  },
  "artifacts": [                     // ≥1: основной + вбэндленные ЭКСКЛЮЗИВНЫЕ deps (§4.2)
    { "file": "artifacts/RNAfold.wasm", "sha256": "4c85a7…416ef7",
      "wasiTools": ["RNAfold"], "multiplexed": false }
  ],
  "dependencies": [                  // только ОБЩИЕ киты (§4.2), точные пины (§8)
    // { "id": "numpy", "version": "2.2.5", "sha256": "…" }
  ]
}
```

Поля, перешедшие из текущего WASM-манифеста и обязательные к переносу:
`sha256` (целостность/кэш), `wasiTools` (имена подкоманд), `multiplexed`
(префиксовать ли имя тула в argv: seqtk — да, RNAfold — нет),
а также способ подачи stdin (`stdinAsFile`: seqtk — файл, RNAfold — реальный fd 0).

### 5.2. `instruction.md`

Агент-facing проза: возможности, флаги/API, когда использовать, чего НЕ делать
(напр. RNAfold: `-g` зависает, `--noDP` только с `-p`). Версионируется **вместе
с бинарём** — лечит дрейф доков (мы поймали его на `--noDP`).

- **Инъекция always-on** (см. §7), но **с бюджетом ~1–2k токенов** на Kit.
- Рекомендуемая форма: **строка-саммари** (всегда в контексте) + компактное тело.
- **`instruction.md` остаётся ручной прозой** (суждение: когда/зачем/чего НЕ
  делать). Точная вызываемая поверхность приезжает **отдельным авто-дайджестом**
  из манифеста (§5.3): операции `id` + summary + сигнатуры `params` (+ опц. один
  worked-example из `golden.input`). Проза и дайджест держатся в общем бюджете
  ~1–2k токенов. Так агент видит и суждение (проза), и точный API (дайджест) без
  дрейфа доков — потому что дайджест выводится из манифеста, а не пишется руками.

### 5.3. `manifest.json` — вызываемая поверхность (strict/loose)

**Манифест ≠ `kit.json`.** `kit.json` несёт метаданные (провенанс, версия,
sha256, deps, runtime). **Манифест описывает, ЧТО и КАК у кита можно вызвать** —
поверхность, которую видит и заполняет агент. Сердце предсказуемости и
проверяемости.

**Два режима (`mode`):**

- **`strict` — именованные операции.** Закрытый список операций с
  типизированными параметрами; агент **не видит сырых флагов/argv** — выбирает
  операцию и заполняет `params`, командную строку строит система (модель
  Galaxy/CWL/MCP, §16). Опасный флаг (`RNAfold -g`) недостижим — его нет среди
  операций, blacklist не нужен. Дефолт для WASI-CLI и тонких whl.
- **`loose` — код в песочнице.** Для широких библиотек (numpy/scipy/sympy), где
  API бесконечен и типизировать его нельзя. Агент пишет код; манифест несёт
  **import-allow-list** (какие пакеты разрешены) вместо операций. Модель
  «Code Mode» (§16).

```jsonc
// strict-кит
{ "kit": "viennarna", "mode": "strict",
  "operations": [{
    "id": "fold",
    "summary": "MFE-структура: dot-bracket + энергия",
    "params": { "sequence": { "type": "string" },
                "temperature": { "type": "number", "optional": true } },
    "output": { "format": "dot-bracket+mfe" },
    "golden": { "input": { "sequence": "GGGAAACCC" }, "expect": "(((...)))  -1.20" }
  }]
}
// loose-кит
{ "kit": "numpy", "mode": "loose",
  "imports": ["numpy"],
  "golden": { "code": "import numpy as np; print(np.linalg.det([[1,2],[3,4]]))",
              "expect": "-2.0" }
}
```

**Recipe-as-data — манифест единственный источник истины.** Из него механически
выводятся: (а) **Zod-валидатор операции** для pre-flight (§6.2); (б)
**golden-фикстура** для тестов (§12); (в) **дайджест операций** в промт (§5.2).
`instruction.md` при этом **остаётся ручной прозой** — кодоген инструкции НЕ
делаем (проза несёт суждение, не выводимое из схемы). golden живёт **внутри**
манифеста (`operations[].golden`), а не отдельным файлом — поэтому рассинхрон
схема↔тест↔дайджест структурно невозможен. Это вариант «К3» из штурма с одной
поправкой: инструкция не генерится, а пишется руками.

## 6. Унификация вызова — единый тул

Сегодня два тула (`wasmCli`, `mathCompute`), разделённые **по рантайму**. На
агент-facing слое это против стандарта (см. §16). v1 вводит **один тул
`compute`**, под которым прячется выбор движка.

- Форма вызова: `compute({ kit, operation, params })` для strict-китов либо
  `compute({ kit, code })` для loose-китов. `runtime` (wasi/pyodide) и конвенция
  берутся из манифеста, а не задаются агентом.
- **Диспетч под капотом** (после pre-flight §6.2):
  - `wasi`: собрать argv (с учётом `multiplexed`), подать stdin (реальный fd 0
    или `/tmp`-файл по `stdinAsFile`), запустить бинарь в WASI-санбоксе, вернуть
    `{exitCode, stdout, stderr}`.
  - `pyodide`: загрузить `.whl` в Pyodide-инстанс, вызвать заявленную точку
    входа, вернуть результат.
- **Схема входа статична** — она часть префикса промт-кэша (никаких
  `Date.now()`/`Math.random()`).

### 6.1. ИНВАРИАНТ: один тул ≠ одно окружение

Два санбокса (WASI и Pyodide) **не делят файловую систему**. Единый тул обязан
**прятать** разницу рантаймов, но **не создавать иллюзию** общего стейта/ФС: файл,
записанный в Pyodide, **не виден** wasi-бинарю. Это ровно тот failure mode, про
который предупреждает индустрия (multi-environment confusion). В системном
промпте — явная строчка: «это изолированные санбоксы, состояние не общее, данные
между Kit гонять через свой ответ».

> Альтернатива «code-mode» (Python как единственная поверхность, wasi
> вызывается ИЗ Python) рассмотрена и **отложена**: при отсутствии общей ФС
> пришлось бы маршалить stdin/stdout между санбоксами через хост — это плюс
> плумбинг без выигрыша на v1. Возвращаемся к идее в v2/v3.

### 6.2. Pre-flight — валидация до санбокса

Когда агент зовёт `compute`, до запуска wasi/Pyodide проходим чистые
data-проверки. Все возвращают **ошибку-как-данные** (не throw — иначе рвём
стрим, см. core-ai); агент видит структурную ошибку и исправляется следующим
вызовом:

1. **kit привязан** к домену (`attached[]` + транзитив) — иначе отказ.
2. **(strict) `operation` ∈ манифест** — иначе отказ + список доступных операций.
3. **(strict) `params` против Zod-схемы операции** (выведена из манифеста):
   тип / required / enum / диапазон. **Тут умирает `-g`:** его нет среди
   `params`, передать нельзя.
4. **(loose) импорты в `code` ⊆ привязанные пакеты** (kit + транзитивное
   замыкание) — иначе отказ до Pyodide.
5. **Целостность:** артефакты на месте + sha256 (кэш после первой проверки).

Только после 1–5 → сборка argv (`TemplateEvaluator`, как у транспорта) или
py-вызова → вход в санбокс. Стадия 3 — точка enforcement: grammar-constrained
sampling для чужого провайдера недоступен (§16), поэтому предсказуемость =
**инъекция сигнатур в промт (§5.2) + жёсткая валидация на границе (стадия 3)**.
Зависание при валидном входе (бесконечный цикл) ловит **таймаут/лимит памяти в
санбоксе** — второй слой защиты.

## 7. Привязка к домену

- **Только per-domain.** Глобальных Kit, привязанных ко всем доменам, нет.
- **Не привязан → агент не видит и не может вызвать.** Это и есть рычаг контроля
  размера промта: RNA-домену не привязывают астрономию.
- Модель привязки — как у **саб-агентов/скиллов** домена.

### 7.1. capability/dependency — свойство ребра, не кита

«Роль» кита не хранится на ките — она **выводится из того, как кит вошёл в
домен**:

- **Явно привязан** пользователем → выступает **capability**: его `instruction.md`
  **инжектится** в агента.
- **Приехал транзитивно** (зависимость привязанного) → выступает **dependency**:
  его артефакты грузятся в рантайм (чтобы привязанный работал), но `instruction.md`
  в промт **не идёт** — пользователь его не выбирал, и тащить доки всего замыкания
  взорвало бы контекст.

Один и тот же кит (`numpy`) в домене A привязан явно (инжектится), в домене B
приехал через `astropy` (молчит). Поэтому поля `role` на ките нет. Резолвер
считает: `attached[]` (явные) + транзитивное замыкание; инжектит — только
`attached[]`, у кого есть `instruction.md`.

### 7.2. Инъекция инструкций — always-on (принятое решение)

Инжектятся инструкции **явно привязанных** китов — и **сразу все** (не ленивая
подгрузка). Progressive disclosure **не используем** — это лишняя
задержка/неопределённость, а размер контролируется привязкой. Защита держится на
**двух условиях разом**:

1. привязано **мало** Kit (курируемо, ~единицы-десяток);
2. `instruction.md` каждого **мал** (мягкий бюджет ~1–2k токенов).

Если оба держатся — схема здоровая. Нарушение любого (30 Kit × 5k md = 150k
токенов) возвращает болезнь контекста — поэтому бюджет на md фиксируем как норму.

### 7.3. Базовый набор и Library

- **Default = 4 кита** (`numpy`, `scipy`, `sympy` — pyodide; `seqtk` — wasi) едут
  в npm как **шаблоны** `packages/found-bundle/bin/templates/kit/`; математическое
  ядро закрывает **~70–80%**, `seqtk` — лёгкий wasi-пример в базе. При первом
  запуске **сидируются в папку пользователя** (`seedTemplateSubdir`, как базовые
  домены). Хвост — через Library.
- **Library фильтрует/группирует по `tags`** (контролируемый словарь, закрытый
  enum в `@found/types` — как `DOMAIN_TAG_OPTIONS`; кит мультизначный, 1-3 тега).
  Категорий нет — таксономия живёт в тегах, одна либа может быть полезна нескольким
  сферам (`molmass` → chemistry+biology).
- **Переиспользуем существующий тоггл `math`** как механизм включения базового
  набора.
- «Лежит локально» ≠ «активно глобально»: базовый набор **локально доступен**, но
  всё равно **привязывается per-domain** (консистентность модели). Эргономика —
  кнопка «attach recommended» в один клик.

### 7.4. Скиллы — остаются

Kit и Skill сосуществуют. **Skill** — сквозная методология без бинаря (рецепты
верификации, «как подойти к задаче», refusal-границы; см. `found-compute-biology`).
**Kit** — несёт **свою** usage-инструкцию для конкретного бинаря/либы. «Уходим от
скиллов» означает лишь «usage-доки теперь внутри Kit», а не «выпиливаем
скилл-механизм».

## 8. Зависимости

Связи: **kit→kit** (Kit зависит от других Kit) и **domain→kit** (домен зависит
от набора Kit).

**v1 — намеренно просто, без солвера:**
- **Точные пины** (`id@version+sha256`; у нас и так exact-версии, без `^`).
- **Lock-файл на домен** — фиксирует ровно то, что привязано/разрешено.
- **Конфликт = громкая ошибка** (fail-loud), а не авторазрешение.
- Ромбы/циклы — детектировать и отказывать с понятным сообщением.

**Разница изоляции по треку (заложить в модель):**
- **wasi-Kit изолированы** — каждый в своём санбоксе, конфликтов версий нет.
- **whl-Kit делят ОДИН Pyodide-интерпретатор** — два разных `numpy` в одном
  интерпретаторе невозможны. Значит набор whl-Kit на домен должен быть
  **со-устанавливаемым**; конфликт версий whl — реальный и проверяется при
  разрешении.

**Связь с бэндлингом (§4.2):** именно общий интерпретатор диктует правило
«эксклюзивные deps вбэндлены, общие — отдельный кит». Эксклюзивный whl лежит
внутри своего единственного потребителя (дублей нет по определению); общий whl
живёт **одним** китом, который привязанные киты делят — иначе в интерпретатор
прилетели бы две копии. Проверка со-установимости = проверка, что у всех
привязанных + транзитивных китов общие зависимости сходятся в одной версии.

> Солвер (conda-класс) и авто-пайплайн — не v1.

## 9. Реестр и дистрибуция

- **Резолв через наш хэш-пиннутый реестр** (открытый гит / позже OCI-реестр,
  напр. ghcr — см. §16). Реестр — content-addressed, `sha256` обязателен и
  **проверяется при загрузке**.
- **git в `provenance` — только метаданные** (откуда взято, upstream), **не точка
  загрузки**. Git-тег мутабелен → доверяем хэшу ассета, не тегу.
- **Точка загрузки — `kit.json.artifacts[].url`** (решение v1, реализовано в
  фабрике). Это *наш* Release-эндпоинт, отдельный от upstream-`provenance.repo`.
  URL **вычисляется по шаблону** `<base>/<id>@<ver>/<file>` (`tooling/lib/release-url.mjs`),
  пишется в `kit.json` **заранее** (до существования байтов — до публикации это
  dangling 404) и «оживает» только после пуша тега `<id>@<ver>` через CI:
  `publish.mjs` называет Release `<id>@<ver>` и грузит ассеты под `basename(file)`,
  поэтому предсказанный URL и реальный совпадают **по построению**. Целостность —
  по `sha256`, не по ссылке. Подробности и инвариант: `.claude/rules/publish.md`.
  При переезде реестра (ghcr/OCI) меняем `RELEASE_BASE` один раз +
  `npm run backfill-urls`.
- **Базовый набор** — в npm как шаблоны `packages/found-bundle/bin/templates/kit/`;
  при первом запуске **сидируется в пользовательскую папку Kit** (по аналогии с
  базовыми доменами — `seedTemplateSubdir`). Пользовательская папка —
  `${FOUND_KITS_DIR}/<kit-id>/` (предлагается `FOUND_KITS_DIR` = `${DATA_DIR}/kits`,
  по аналогии с `FOUND_DOMAINS_DIR`).
- **Default-артефакты не в git.** Байты (`*.whl`/`*.wasm`) под
  `templates/kit/<kit-id>/artifacts/` — **gitignored**; в git едет только
  определение Kit (`kit.json` / `manifest.json` / `instruction.md` / `LICENSE`).
  В npm-бандл артефакты попадают на этапе сборки (копируются вместе с шаблонами
  в `found-bundle/bin/templates/kit/`). Раз git больше не страхует от неполного
  бандла, перед сборкой работает гард `scripts/verify-kit-artifacts.mjs`
  (presence + sha256 по `kit.json`, падает с ненулевым кодом при пропаже или
  несовпадении хэша) — по образцу `scripts/vendor-wasm.mjs`. Движок
  (`found-bundle/bin/pyodide/`) собирается как прежде, отдельно от Kit.
- **Хвост через Library** — скачанные Kit **ложатся в ту же пользовательскую папку
  Kit** (как скачанные домены ложатся в пользовательскую папку доменов). Поток:
  запросил в Library → реестр отдаёт Kit → **проверка `sha256`** → распаковка в
  `${FOUND_KITS_DIR}/<kit-id>/` → доступен для привязки к домену.
- **Папка-folder, а не blob-кэш.** Единица хранения — папка Kit (как домен), а не
  content-addressed blob. `sha256` из `kit.json` **верифицирует артефакты** при
  скачивании и загрузке (целостность), но хранение — пофолдерное, как у доменов.
- Обслуживание: `found kit pull <id>` / `--all`, `found kit verify` (сверка
  хэшей пользовательской копии), `found kit list`.
- **`verified`-флаг:** `true` — Kit собрали/проверили мы; `false` —
  user-supplied (см. §11).

## 10. Публикация домена

- Домен публикуется со **ссылками** на Kit (`id@version+sha256`), **не с
  бинарями**. Домен — отдельно, Kit — отдельно; в JSON домена только ссылки +
  провенанс «где взять».
- При открытии скачанного домена система говорит: «не хватает Kit X, Y — вот где
  глянуть». **Юзер сам** ставит их через Library. **Авто-выкачивания из
  произвольного гита нет.**
- Ссылка несёт **`id@версия+hash`**, а не только имя — иначе юзер поставит
  *похожий*, а не *тот же* Kit (воспроизводимость).
- **Лицензии** показываются **в момент установки через Library** (слой реестра),
  не на слое домена — домен лишь *рекомендует*, редистрибуции нет, поэтому
  лицензионная ответственность переезжает в реестр.
- **Воспроизводимость** держится на `hash` + зеркале в реестре (даже если
  upstream-git исчез).

## 11. Безопасность и детерминизм

- **Санбоксы — наша защита.** WASI: нет сети, только preopen `/tmp`. Pyodide: WASM-
  изоляция. Пользовательский Kit исполняется в той же песочнице — это и есть
  митигатор «чужого кода».
- **Лицензии/редистрибуция.** Некоторые ассеты **запрещены к редистрибуции**
  (`naview.c` в ViennaRNA — исключён из сборки). Реестр может хранить *ссылку*,
  но не право класть бинарь к себе. Метаданные лицензии едут с Kit и
  показываются.
- **Детерминизм.** Наше правило промт-кэша требует байт-стабильного `content`.
  На сторонний бинарь это не навяжешь → флаг `verified` (наши Kit
  детерминизм-протестированы) vs user-supplied. **golden-пример** служит
  determinism-фикстурой (см. §12).
- **Схема единого тула — статична** (часть кэш-префикса).

## 12. Тестируемость и I/O-контракт

`manifest.json` (§5.3) описывает вход/выход Kit, делая связь **проверяемой и
тестируемой**. Зеркалит доменный `dcc` (`contractMd` проза + `schema` структура).

**Что описывает:**
- **input:** для `wasi` — схема `args` + формат stdin («RNA-строка», «FASTA»);
  для `pyodide` — сигнатура вызова / что ожидает.
- **output:** формат stdout («dot-bracket + MFE», «FASTQ», JSON), семантика
  exit-code и stderr.
- **golden-пример:** `input → expected output`.

**golden-пример — один артефакт, три применения:**
1. **Контракт-тест** — скормили заявленный вход, проверили заявленный выход
   (как RNAfold: `GGGAAACCC` → dot-bracket + MFE).
2. **Determinism-тест** — фикстура для существующего
   `tool-content-determinism.test.ts` (два прогона = байт-в-байт).
3. **Worked example** — тот же пример идёт агенту как образец вызова в `instruction.md`.

Плюс **hash-проверка** в стиле `manifestVerify.test.ts`.

**Подводные камни контракта (заложить в дизайн):**
- **Не строить богатую систему типов.** Научный I/O грязный (free-text FASTA,
  ad-hoc вывод). На старте — **грубые format-теги + golden-пример**, не типовая
  решётка. Исполняемый пример ценнее изящной схемы.
- **Вывод CLI часто неструктурированный текст**, не JSON. Для многих wasi-Kit
  output-контракт = «формат строки / regex для ассерта», а не строгий парсер.
- **Композируемость — только проверка совместимости** (по format-тегам)
  типизирует граф зависимостей. **Авто-пайплайн не v1** — контракт лишь
  *позволяет проверить* совместимость и *даёт агенту* инфу пайпить руками.
- **Валидация на границе** — input-схема отклоняет кривой вход **до** запуска
  санбокса и возвращает агенту структурированную ошибку (errors-as-data по
  AI-правилам), а не загадочный ненулевой exit. Механика — pre-flight §6.2.

### 12.1. Слои тестов (итерируются по манифестам)

golden живёт **внутри** манифеста (`operations[].golden`), манифест — источник,
поэтому тесты **итерируются по манифестам всех китов** (как
`tool-prompt-coverage.test.ts` по реестру): добавил кит с манифестом → покрыт
автоматически.

| Слой | Что проверяет | Прецедент |
|---|---|---|
| **Schema-parse** | валидный манифест парсится, кривой отлетает; strict-поля не лезут в loose, wasi не в pyodide | `manifest.output.test.ts` (транспорт) |
| **Integrity** | артефакты на диске = sha256 манифеста | `manifestVerify.test.ts` |
| **Golden-контракт** | strict: `golden.input` → реальный диспетч → санбокс → сверка с `golden.expect` (точное / regex / format-тег) | Galaxy `<tests>`, bioconda `test.commands` |
| **Golden-smoke** | loose: `golden.code` исполняется, выход = `golden.expect` («колесо грузится и детерминированно считает») | bioconda `test.imports` |
| **Determinism** | golden дважды → байт-в-байт | `tool-content-determinism.test.ts` (golden = фикстура) |

| **Dep-graph** | циклы/ромбы; со-устанавливаемость whl (два numpy → громкая ошибка) | новое (специфика общего Pyodide-интерпретатора, §8) |

## 14. Дорожная карта

- **v1 (этот документ):** сущность `Kit`, два формат-трека, единый тул,
  хэш-реестр, привязка per-domain, контракт+golden, базовый набор в npm + хвост
  через Library.
- **v2 — нативная Python-песочница:** снимает потолок Pyodide (весь PyPI,
  нативка, потоки, subprocess к бинарям, HPC-на-CPU). Цена: юзер ставит
  песочницу сам (мы не провижним Python во время `npm install`), теряется
  zero-config/часть оффлайна, нужна изоляция (Docker/microVM). **Звёздочка:**
  «всё» не включает GPU/CUDA/AlphaFold-класс — нет железа, не приедет.
- **v3 — гибрид:** Pyodide как бандл-база по умолчанию (дух v1) **+ опциональный
  внешний real-Python backend** для тяжёлой нативки, подключаемый по модели MCP
  («принеси свой»). Дефолт остаётся appliance'ом; два кодовых пути.
- **Дальше:** WASI preview2 / Component Model (эволюция wasi-трека);
  другие языки-рантаймы как wasm (webR для R и т.п. — это контент на
  существующем треке).

## 16. Приложение — прецеденты из ресерча (self-contained)

**Дистрибуция большого каталога (откуда «ядро + ленивый хвост + кэш по хэшу»):**
- **biowasm/Aioli** — npm-лоадер крошечный, `.wasm` тянутся с CDN по `name/version`,
  оффлайн = вендорить ассеты вручную.
- **Pyodide** — маленькое ядро + `loadPackage`/`micropip`, хэш-пин из PyPI JSON,
  lock-файл; «оптимизируешь размер — бери loadPackage, не micropip».
- **OCI-артефакты (wkg/ORAS/ghcr)** — `.wasm` как OCI: `sha256`-манифесты,
  подписи/SBOM, **нет multi-arch матрицы** (wasm арх-нейтрален); Homebrew ушёл на
  ghcr ради бесплатного безлимит-трафика OSS.
- **conda/bioconda** — каналы + солвер + lock; 3000+ пакетов держатся на
  recipe-as-data + CI; один рецепт → пакет + контейнер.
- **HuggingFace Hub** — content-addressed `blobs/` + symlinked `snapshots/`,
  `hf cache verify`/`prune`; **симлинк-дедуп ломается на Windows**; кэш растёт
  безгранично.
- **VS Code Marketplace** — UI-установка, **подпись проверяется на установке** +
  trust-prompt; оффлайн = VSIX sideload.
- **esbuild/sharp** — per-platform `optionalDependencies`; боль: `--no-optional`
  ломает; postinstall под прицелом supply-chain.

**Форма exec-поверхности для агента (откуда «единый тул»):**
- Frontier-вендоры (OpenAI/Anthropic/Gemini) — **один Python-санбокс**; CLI/bash
  **внутрь** того же тула (Anthropic) или отдельным shell-тулом (OpenAI), почти
  никогда per-language.
- Сторонние санбоксы (E2B/Modal/Daytona) — один полиглот `run_code(code,
  language=…)`; язык — **параметр**, не тул.
- Тренд (Anthropic «Code execution with MCP», Cloudflare «Code Mode») — **одна
  exec-поверхность + всё остальное как вызываемые из кода API**; экономия
  токенов 80–99%; Anthropic документирует, что **два exec-окружения путают
  модель** (наш инвариант §6.1).
- **WASM Component Model** — полиглот-конвергенция (много языков, один рантайм,
  типизированные WIT-интерфейсы); как агентский стандарт пока **позиционирование**,
  не практика.

### 16.1. Ресерч манифестов (2026-06) — откуда «именованные операции» и «loose-код»

Глубокий поиск по первоисточникам (харнесс `deep-research` валил верификацию —
собрано напрямую через firecrawl; структурные факты сходятся, дословные цитаты
проверены). Вердикт: **именованные типизированные операции (командную строку
строит система) — доминирующая модель и в науке, и в LLM-tooling; «валидируемые
сырые флаги» как осознанный паттерн в источниках не встречается.** Для широких
библиотек индустрия осознанно уходит в свободный код в песочнице («Code Mode»).

**Центральная развилка — кто строит argv (все: операции, не сырые флаги):**
- **Galaxy / Planemo** — типизированные `param` (`integer/float/select/boolean/data`,
  min/max, `sanitizer`); `<command>` Cheetah-шаблон строит argv; юзер заполняет
  параметры, не пишет флаги. `<tests>`: `assert_contents` (`has_text`,
  `has_n_columns`), сравнение `diff`/`sim_size`/`md5`, golden в `test-data/`.
  [tool_xml](https://galaxy-iuc-standards.readthedocs.io/en/latest/best_practices/tool_xml.html) ·
  [test_format](https://planemo.readthedocs.io/en/latest/test_format.html)
- **CWL CommandLineTool** — типизированные `inputs` + `inputBinding{prefix,
  position}`; раннер собирает строку из `baseCommand` + bindings по `position`.
  [v1.2](https://www.commonwl.org/v1.2/CommandLineTool.html)
- **WASM Component Model (WIT)** — `func` с типизированными параметрами/результатами
  (`record/variant/enum/option/result/list`); *«callers are bound to the typed
  interface»*. [WIT](https://component-model.bytecodealliance.org/design/wit.html)
- **MCP / OpenAI / Anthropic** — `inputSchema`/`parameters` = JSON Schema
  (`enum`/`required`/`additionalProperties:false`); модель заполняет типизированные
  поля. [MCP Tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) ·
  [OpenAI](https://developers.openai.com/api/docs/guides/function-calling)

**Валидация до запуска:**
- **Anthropic strict tool use** — *«compiles tool `input_schema` into grammars …
  cached for up to 24 hours»*; кривой вызов нельзя даже сгенерировать (нам это
  недоступно для чужого провайдера → у нас pre-flight на границе, §6.2). ⚠️ схема
  гарантирует **форму, не корректность значения** → golden обязателен.
  [strict tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use)
- **Allow-list перед exec** — Trail of Bits: *«validates commands against this
  allow list before execution»*; Hermes Agent: allowlist + блок опасных команд.
  [Trail of Bits](https://blog.trailofbits.com/2025/10/22/prompt-injection-to-rce-in-ai-agents/)

**strict↔loose — code-mode для широких либ (наш loose-трек = фронтир, не костыль):**
- **Anthropic «Code execution with MCP»** — тулзы как code-API: контекст
  **150k → 2k токенов, −98.7%**.
  [статья](https://www.anthropic.com/engineering/code-execution-with-mcp)
- **Cloudflare «Code Mode»** — *«LLMs are better at writing code to call MCP than
  at calling MCP directly»*; песочница изолирована от сети, тулзы = типизированные
  TS-биндинги. [Code Mode](https://blog.cloudflare.com/code-mode/)
- **OpenAI Code Interpreter** — *«write and run Python code in a sandboxed
  execution environment … run iteratively»*: free-form escape hatch рядом с
  типизированным function-calling.
  [CI](https://platform.openai.com/docs/assistants/tools/code-interpreter)
- Граница loose честно очерчена Pyodide: **нет threading / multiprocessing /
  subprocess / sockets**.
  [WASM constraints](https://pyodide.org/en/stable/usage/wasm-constraints.html)

**Тестируемость / целостность:** Galaxy `<tests>`, **bioconda** `test.commands`/
`test.imports` + `source.sha256`, **nf-test** `snapshot(...).match()` + `md5()`,
**conda** `meta.yaml → test.*`. Наш «golden на операцию + golden-smoke (≈
`test.imports`) + sha256 + determinism» — прямая калька.
[bioconda](https://bioconda.github.io/contributor/guidelines.html) ·
[nf-test](https://www.nf-test.com/docs/assertions/snapshots/) ·
[conda meta.yaml](https://docs.conda.io/projects/conda-build/en/stable/resources/define-metadata.html)

**Где прецеденты расходятся:** (1) момент валидации — на генерации (Anthropic/
OpenAI) vs на границе перед запуском (Galaxy/CWL/MCP); нам доступен только
второй. (2) Степень скрытия argv — CWL даёт `position` (частичный контроль), Galaxy
прячет полностью; для kit выбран полный (агент argv не видит). (3) Богатство
типов — WIT строгий, JSON Schema слабее; для грязного научного I/O «типы как
правило string» достаточно (§12).
